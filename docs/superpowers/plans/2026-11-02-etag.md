# ETag Precondition Inspector Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Track steps and actual results in the plan-owned ledger.

**Goal:** Inspect recorded entity-tag conditions and their bounded HTTP model locally.

**Architecture:** A pure TypeScript scanner and tri-state evaluator feed a Vapor view using shared controls. Pure constants support static guides and synthetic examples.

**Tech Stack:** Existing Vite+, Vue 3.6 RC/Vapor, shadcn-vue and five-locale i18n; no new packages.

**Spec:** [ETag design](../specs/2026-11-02-etag-design.md)

## Global Constraints

- Only army-knife; preserve analytics, PR #145, dependencies, CI/Pages settings and font/license policy.
- Active values: 8 KiB UTF-8 total, 64 tags and 64 empty members per conditional field, 512 UTF-8 bytes per tag.
- 2,048-character immediate threshold; shared 800ms delay/manual/cancel. Bounded parsing is synchronous.
- Six modeled methods, explicit header presence, unknown current ETag and all-or-error active syntax validation.
- No input/result transmission, URL/storage state, telemetry, external fonts or WebMCP; explicit JSON export only.
- Keep independent branch isolation in this clean dedicated checkout; baseline full unit suite must pass.

## Review Focus

- Empty present conditions must not silently become absent; wildcard and quoted star differ.
- Unknown current ETag must not hide a deterministically failed strong comparison or invent a status.
- Commas/backslashes/octet characters must not be decoded with quoted-string or Unicode-normalization rules.
- Hidden/disabled input and rejected edits must not leave stale decisions/exportable data.
- Modeled statuses must disclose normal-check assumptions, skipped comparisons and the already-applied-change exception.
