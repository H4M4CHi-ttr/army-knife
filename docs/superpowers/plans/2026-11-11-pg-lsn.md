# PostgreSQL WAL LSN Comparison Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in this session.

**Goal:** Compare recorded WAL positions with exact bytes and segment offsets.
**Architecture:** Pure bounded BigInt function, one Vapor view and five dictionaries/guides.
**Tech Stack:** Existing pinned Vite+, Vue 3.6 RC/Vapor, shadcn-vue and Playwright.
**Spec:** [Design](../specs/2026-11-11-pg-lsn-design.md)

## Global constraints
64 raw UTF-8 bytes per LSN; two 1..8-digit hex halves with outer SP/HTAB only.
Unsigned 64-bit positions; all computed byte/count values exported as decimal
strings. Segment size powers of two 1..1024 MiB, default 16. Always immediate.
No input/result requests, logs, URL/storage state, new package/font/CDN,
telemetry, WebMCP or deployment settings/destination.

## Review focus
High-half rollover and one-byte changes beyond Number.MAX_SAFE_INTEGER;
zero sentinel vs real record location; segment-boundary naming ambiguity;
stale exports after either rejected edit; input lifecycle/privacy.

`PG_LSN_LIMITS.inputBytes`, `PG_WAL_SEGMENT_MIB` and a synthetic `PG_LSN_SAMPLE`.
