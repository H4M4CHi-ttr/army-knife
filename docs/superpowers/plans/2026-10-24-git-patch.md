# Git Patch Inspector Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; obtain one independent whole-branch review.

**Goal:** Inspect a recorded Git patch without applying it or transmitting its contents.
**Architecture:** Bounded pure TypeScript parser, Vapor view, existing execution/input/output controls, five-language messages and static guides.
**Tech Stack:** Existing Vite+, Vue 3.6 RC/Vapor, shadcn-vue and TypeScript.
**Spec:** `docs/git-patch.md`

## Global Constraints

- Only H4M4CHi-ttr/army-knife; preserve PRs #145/#149 and the mounted empty repository.
- No new dependency, transmission/persistence of input, telemetry, remote fonts, execution or patch application.
- UTF-8 64 KiB / 2,000 lines / 50 files / 200 hunks / 20-digit range starts.
- At most 2,048 units instant; otherwise existing 800ms/manual/cancel controls.
- Five languages, light/dark, keyboard, narrow layout; final-commit quality and Pages checks.

## Review Focus

- Hunk content resembling file headers remains data and counts exactly.
- Quoted and hostile paths remain inert text, including invisible/control escapes.
- Truncated/binary/combined input removes previous usable results rather than showing partial totals.
- Large range starts preserve exact values; omitted and zero counts follow unified-diff semantics.
- Cancellation, rejected paste, clear and navigation remove stale results/exports; input stays memory-only.
