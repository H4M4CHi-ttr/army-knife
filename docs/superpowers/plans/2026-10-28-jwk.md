# JWK inspector Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. The user authorized autonomous implementation through normal merge and existing Pages verification.

**Goal:** Inspect recorded public JWK/JWKS structure, metadata and exact RFC 7638 SHA-256 identifiers locally.

**Architecture:** A bounded TypeScript parser produces an allowlisted report and native Web Crypto thumbprints. A Vapor view uses shared execution/input/output controls; five locales feed both UI and static guides.

**Tech Stack:** Existing Vite+, Vue 3.6 RC / Vapor, shadcn-vue, TypeScript and Web Crypto. No new dependencies.

**Spec:** [docs/jwk.md](../../jwk.md)

## Global Constraints

- Only army-knife; do not modify GA, another contributor's branch, CI settings or dependencies.
- 64 KiB input, 32 keys, 2,048-character immediate threshold, 800ms debounce, 5s total deadline.
- Public-only allowlisted outputs; private/symmetric keys reject the document; no partial result.
- Existing strict JSON precision/depth/node limits; exact RSA integers and canonical base64url.
- No external input/result transmission, persistence, URL state, telemetry, fonts or WebMCP.
- Existing five languages, themes, font licenses and browser projects remain required.

## Review Focus

- Canonical base64url padding bits and unsigned RSA leading zeroes must not yield ambiguous thumbprints.
- Private fields or unknown extensions must never be echoed in reports or errors.
- Same kid versus same key are distinct diagnostics; metadata must not alter thumbprints.
- Editing, rejected imports, cancellation and late digests must invalidate exportable output.
- Unsupported algorithms/curves and mathematically unchecked points must not appear verified.
