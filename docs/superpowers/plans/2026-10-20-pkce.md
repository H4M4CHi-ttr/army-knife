# PKCE Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement these tasks inline.

**Goal:** Add one practical browser-only PKCE generator and existing-verifier check.
**Architecture:** Bounded native Web Crypto engine, shared cancellable execution controller, dedicated Vapor view and five localized static guides.
**Tech Stack:** Existing Vite+, Vue 3.6 RC/Vapor, shadcn-vue, TypeScript and Web Crypto.
**Spec:** `docs/pkce.md`

## Global Constraints

- Only H4M4CHi-ttr/army-knife; keep other open PRs untouched.
- No added dependency, telemetry, external runtime assets or user-data persistence/transmission.
- Verifier 43–128 ASCII unreserved; state omitted or 16–128; S256 only; 5-second watchdog.
- Five languages, light/dark, keyboard and narrow layouts; all existing quality gates required.

## Review Focus

- A valid verifier containing dot/tilde must be hashed exactly without normalization.
- Bad numeric settings, Unicode or oversized paste must not leave usable stale output.
- Cancel, clear, navigation or a new request while hashing must reject a late result.
- An unavailable/rejected Crypto API must never trigger an insecure fallback or expose input.
- Generated values and private markers must remain absent from URLs, persistence and requests.
