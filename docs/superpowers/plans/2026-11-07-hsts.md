# HSTS inspector implementation plan

The recurring user request authorizes autonomous selection, implementation,
independent review, a draft/ready PR, normal protected merge and existing Pages
verification. Scope: [bounded design](../../hsts.md); main base `629a6ee`.

1. Write failing pure tests for `inspectHsts(input): HstsReport`, then implement
   the bounded quote-aware directive scanner and exact BigInt duration summary.
   Cover quoted digits, case, extensions, duplicates, zero, malformed inputs and
   every raw-byte/digit/slot/directive boundary. Errors use input-free ToolError
   codes and all failures produce no report.
2. Write failing real Vapor tests, then add `HstsTool.vue`, localized messages,
   guide, catalog/icon and lazy route. Exercise immediate/deferred/manual/cancel,
   rejected paste, inert values, exact explicit export and memory disposal.
3. Add production browser tests for five locales, both themes, keyboard, 390px,
   real JSON download, precise integers, errors, delayed controls, preferences,
   clearing and exact-dist request/privacy auditing. Update README, overlap and
   testing documentation. Reuse existing font/build infrastructure.
4. Run typecheck, lint, unit/Vapor, Rust/Clippy/WASM, script/license tests, build,
   dist checks and four browser projects on the final commit. Obtain independent
   review, resolve material issues, create draft PR and record evidence. Mark
   ready only after verification. Recheck main, expected head, checks and review
   rules, merge normally and inspect the existing main Pages run and live tool.

Review risks map to parser tests (quoted delimiters, duplicate extensions, exact
duration and zero interpretation), view tests (invalid/rejected stale exports),
and E2E (inert values, lifecycle, downloads, privacy, locales and themes).
