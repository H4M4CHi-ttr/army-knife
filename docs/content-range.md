# HTTP Content-Range検査

記録済みの応答フィールドから、両端を含む区間長、宣言された全体長、区間前後の
バイト数を正確に確認します。既存HTTPバイト範囲検査は要求Rangeと明示サイズの
計算で、このツールは応答側の値を読む別の用途です。通信や再開要求は送りません。

フィールド値、または `Content-Range:` から始まる1行を入力します。
結果は常に即時反映し、正規表記とすべての値を表示します。完全なJSONは明示操作で
コピー・保存できます。空欄とクリア後は結果を出さず、不正・拒否された入力では
古い結果と出力操作を消します。未知の値と該当しない値を0に置き換えません。

## 受け付ける形式

- `bytes 先頭-末尾/全体長`：0始まり、両端を含み、末尾は先頭以上、全体長は末尾より大きい値。
- `bytes 先頭-末尾/*`：全体長は不明。区間長と先頭より前の長さは計算でき、後ろの長さ・全体を覆うかは不明。
- `bytes */全体長`：非充足範囲の形式。宣言された全体長だけを保持し、区間・区間長・前後・全体を覆うかは該当なし。`bytes */0` も受け付けます。本文が0バイトとは判断しません。

区間長は末尾−先頭+1、前は先頭、後ろは既知の全体長−末尾−1です。
先頭0かつ末尾+1が既知の全体長なら、算術上は全体を覆います。これらは受信済みの
データ量やダウンロード進捗ではありません。content codingがある場合は符号化後の
選択された表現に対するバイト数で、展開後や通信フレームの長さではありません。

合成サンプルは先頭 `9007199254740993`、末尾 `9007199254741992`、全体長
`9007199254742993`。区間長と後ろの長さはそれぞれ1000バイトです。
Number.MAX_SAFE_INTEGERを超える位置もBigIntで計算し、JSONの整数は10進文字列で
出力します。nullは不明・該当なし、真偽値は全体を覆うかの算術情報です。

## 上限と非対応

加工前UTF-8 **256バイト**、各10進数は先頭ゼロを含めASCII **1〜40桁**です。
計算結果は41桁になる場合もあり、丸めません。先頭ゼロ・単位名の大小文字を正規化します。
単位はbytesのみで、その後のASCII空白は1個。外側のASCII空白・タブと任意の
Content-Range接頭辞は許容します。改行・折り返し・別単位・複数フィールドや区間・
符号・内部の余分な空白は拒否し、部分結果は返しません。

構文と内部の算術整合だけを検査します。HTTPステータス206/416、元の要求との
対応、Content-Length、本文、multipartの全体構造、展開、再開の安全性は検証しません。
`*/長さ` から元の要求が非充足だったことを証明することもできません。
一般のヘッダー診断パネルIssue #53を完了する変更ではありません。

## 実行・データ・検証

上限内の軽い計算のため、自動適用がオフでも常に即時反映します。
入力・結果はメモリ内だけで、ツール・言語変更や再読み込みで破棄します。
明示ドロップしたUTF-8ファイルはローカル読込し、BOMも保持してASCII構文として
拒否します。不正UTF-8・上限超過も拒否します。入力や結果の外部送信、URL化、ログ、
永続保存、新規API・依存・テレメトリ・外部フォント・WebMCP・公開設定は追加しません。
5言語・ライト/ダーク・キーボード・390px幅で既存のVapor/shadcn-vue部品を使います。

[RFC 9110 §§14.1, 14.4](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.4)を参照。
純粋関数で境界・精度・未知・非充足・構文・上限、実Vaporで即時実行・拒否・
明示出力・言語・破棄を検査します。4プロジェクトのproduction E2Eで各言語・両テーマ、
実JSON保存、ファイル、キーボード/幅、URL/Storage/通信への入力漏洩を検査し、
既存Pagesの公開後も同じ実操作を確認します。
