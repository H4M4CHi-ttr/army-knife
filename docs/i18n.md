# Interface languages

Army Knife supports 11 UI locales. The public URL segment is case-sensitive.

| Locale | Native language name | Font pack |
| --- | --- | --- |
| `ja` | 日本語 | `ja` |
| `en` | English | `en` |
| `zh-CN` | 简体中文 | `zh-CN` |
| `zh-TW` | 繁體中文 | `zh-TW` |
| `ko` | 한국어 | `ko` |
| `es` | Español | `en` |
| `fr` | Français | `en` |
| `de` | Deutsch | `en` |
| `pt-BR` | Português (Brasil) | `en` |
| `id` | Bahasa Indonesia | `en` |
| `vi` | Tiếng Việt | `en` |

## Coverage

Each locale supplies all 717 interface messages, including settings, tool names,
descriptions, controls, errors, execution controls and disabled/unknown-page
states. Each of the 30 catalog tools has a translated static guide with usage,
example interpretation and limitations. Technical example inputs are shared;
translated prose preserves their syntax, numeric limits and units.

The static generator creates 341 language-specific documents: 11 homes and 330
tool pages, plus the historic Japanese root alias. Their titles, descriptions,
canonical URLs, reciprocal `hreflang` links and sitemap entries are generated
from the same catalog. Guides remain readable without JavaScript.

The UI locale is distinct from data a tool works with. In particular, the dummy
text generator retains its existing Latin/English/Japanese/Chinese/Korean source
corpora. The shortcut dictionary retains its documented English/Japanese action
and context data and original attribution notices. Adding a UI language does not
expand either dataset or the tools' supported input formats.

## Selection, search and fonts

Settings, the app header and static pages share native names from
`src/lib/locales.ts`. Browser preferences are matched in order using canonical
BCP 47 language tags. Regional variants such as `es-MX`, `fr-CA`, `de-AT`, `id-ID`
and `vi-VN` resolve to their supported language. All Portuguese preferences
currently resolve to `pt-BR`, the available Portuguese translation. For Chinese,
an explicit Hans/Hant script takes priority over the region. Unsupported or
malformed tags are skipped; English is the final preference fallback.

The existing root-document policy remains Japanese for a first root visit. A
saved language choice, or a direct language-specific URL, selects that language.
Legacy hash links use the saved or detected language. Changing the language
preserves theme, favorites, enabled tools and auto-apply preferences. Tool inputs
are cleared when navigating between language pages, as with existing navigation.

Search matches translated tool names/descriptions and the existing technical
keywords. All query words must match. The six added Latin-script locales allow
omitting accents; German `ß` also matches `ss`, and Vietnamese `đ` matches `d`.
This is the current substring search, without a model or a new dependency.
The separate experimental natural-language search/classifier work must add these
locales to its intent data/training and evaluation when it is integrated.

The six additions reuse `/fonts/en.css`, the existing Noto Sans variable font
and Sarasa J code font. The font loader caches by font pack while keeping the
selected locale in `html[lang]`. The existing Noto package contains Latin,
Latin Extended and Vietnamese subsets. No additional font archive or duplicate
font family is needed. See [fonts](fonts.md) for source pins and licensing.

## Adding another language or message

1. Register its public tag, native name and font-pack mapping in
   `src/lib/locales.ts`. The feature-grouped original five languages use
   `CoreLocale`; all public consumers use `Locale` and `LOCALES`.
2. Add `src/i18n/locales/{locale}.ts` satisfying `LocaleMessages`, then register
   it in `src/i18n/messages.ts`. The English core defines the required keys.
   Translate every key explicitly; do not spread English as a translation.
3. Preserve named placeholders and Vue i18n literal syntax. Keep programming
   expressions, identifiers, units, numeric limits and sample payloads correct.
4. Add `src/lib/guides/{locale}.ts` with all `ToolId` guides and `GuideLabels`,
   then register it in `src/lib/tool-guides.ts`. Keep technical example inputs
   identical to the English source and translate the explanatory fields.
5. Check browser-tag matching, appropriate font coverage and UI layout. A new
   script or right-to-left language requires its own font/layout assessment.
6. Run the existing type, translation, guide, Vapor, static output and browser
   gates. `tests/e2e/locales.spec.ts` exercises the six added languages through
   real Settings navigation, search, CIDR results, fonts, themes and reloads.

When adding a tool or an English interface key, update **all 11** translations
and relevant guides. Type checking and exact-key tests reject incomplete
catalogs. The original per-feature dictionaries are assembled in
`src/i18n/core-messages.ts`; per-language additions remain independently editable.
